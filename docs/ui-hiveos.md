顶部统计映射到当前产品已有的机器、CPU 线程、BMC 功耗、分算法算力、BMC 在线和运行实例。原图中的 GPU 数量与美元余额没有对应的可信数据源，因此不伪造数值；CPU 在线标记使用 `C`，不冒充原图的 NVIDIA `N`。缺失或过期数据继续显示 `—`。

使用独立于正式数据库的临时本地样本服务，在浏览器检查了紧凑列表的视觉布局、搜索、收藏、在线/掉线筛选、网格切换、批量选择以及点击矿机进入详情。样本值不进入产品或交付包。生产构建和模块边界检查另行执行；真实 EPYC/BMC 数据仍需现场验收。

本轮通过用户已登录的 HiveOS 页面查看了矿场列表、矿机概览、全局钱包、添加钱包、飞行表四步联动，以及 Custom 矿工配置弹窗。仅导航和填写未保存的表单，未创建或修改线上配置，也未操作线上矿机。

## 已更新

- 全局布局改为横向导航、居中内容区、深灰配色和紧凑列表。
- 飞行表改为页面常驻编辑器：数字货币 → 钱包 → 矿池 → 挖矿软件。根据前一步启用下一级，钱包按币种过滤。
- 在飞行表内创建自定义币种钱包、矿池或矿工，保存后自动回填；共用目录 API 与修订检查。
- 矿池支持复用目录或在矿工中配置；自定义地址在独立配置弹窗输入并保存到任务。目录矿池可逐个选择服务器并调整优先级；所选地址顺序写入飞行表任务、编译快照和自定义矿工环境。保存及应用时拒绝已从目录删除或重复的地址。
- 矿工参数独立配置，字段由适配器描述生成；支持多矿工、任务移除、编辑、复制、币种筛选、搜索、分页和批量应用。
- 钱包弹窗按币种、地址、名称、来源、备注排列，列表展示币种、名称/来源与地址。
- 单机顶部保留实际矿工状态、份额、算法和算力摘要，下方提供信息分页；概览增加按算法独立的历史算力、CPU 插槽/核心/线程、负载、内存、系统、内核、主板、BIOS、网络接口和磁盘。
- 可选硬件采集识别 k10temp/coretemp/zenpower；缺失字段返回 null，不将 NVMe 温度当作 CPU 温度。

## 保留的边界

官方公开的 `hiveos-linux` 仓库说明它是矿机客户端，且其示例配置将矿机指向 `api.hiveos.farm`；不能从该仓库还原云端 Dashboard 的完整页面。官方操作文档可核对钱包、矿池服务器选择、飞行表与矿机操作流程。本轮只在线检索公开镜像目录、源码与文档，未下载系统镜像。参考：[客户端仓库](https://github.com/minershive/hiveos-linux)、[矿机配置示例](https://github.com/minershive/hiveos-linux/blob/master/hive/etc/hive-config.stub/rig-config-example.txt)、[官方入门文档](https://hiveon.com/knowledge-base/guides/how_to_start_mine_in_hiveon_os/)。

目前自定义矿工包收到有序的完整地址列表；XMRig、SRBMiner-MULTI 与 cpuminer-opt 原生适配器仍只将首选地址传给矿工。服务器选择和排序不等于这三个适配器的运行时故障切换，界面已明确提示。该轮 React 构建、Rust WSL 单元测试通过；本地 PostgreSQL/Docker 未启动，因此新交互没有完成浏览器连库验证。

用户当前有运行矿机的 HiveOS 矿场只授予 MONITOR 权限，只能核对概览、统计、活动等可见页面。管理员专属的单机管理界面尚未完整对照。此版是已确认自托管功能范围内的交互重做，不能据此宣称 HiveOS 全站像素级或全部功能 1:1。

交易所 API、钱包余额/美元估值、超频模板、HiveOS 账户计费与邀请系统、官方云端矿池目录、HiveOS 飞行表文件/剪贴板导入不包含在本轮实现。CPU 与 BMC 页面使用 RigDeck 真实采集能力，不伪造原界面的 GPU、驱动或传感器值。

本轮测试节点的“部署运行层”尝试在原子链接更新阶段失败：既有 Docker 夹具把 `/opt/rigdeck/current` 建成普通目录，且不运行 systemd。任务已核实为失败并保留审计、解除测试节点锁；随后备份并更新该夹具的采集脚本验证硬件字段。这不算 Ubuntu 开机恢复或自动部署通过的证据。

`screenshots/` 与此前 `docs/evidence/summary.json` 保留上一阶段证据，不代表本轮 UI；本轮变更可在本地 5173 预览查看。此前构建的 Docker 镜像未在本轮重新发布，部署新界面需重新构建源代码。
