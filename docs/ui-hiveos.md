# HiveOS 界面对照与本轮验证

## 矿机详情补全（2026-10-23）

对照用户自有矿场（FULL 权限）的单机页面，全站差距见 [2026-10-23_hiveos-gap.md](2026-10-23_hiveos-gap.md)。接入方式保持 SSH + 主动上报；计费、余额、交易所、邀请码不做。

- 顶栏图标按 HiveOS 顺序：电源动作（重启 / 关机 / BMC 断电重启、开机、优雅关机、强制断电）、SSH 终端、部署运行层（对应“升级或降级”）、运行命令、选择飞行表、编辑标签、挖矿软件动作（重启 / 启动 / 停止 / 日志 / 控制台 / 逐实例）、算力监视器、Autofan 设定、BIOS、矿机选项、移除、刷新。HiveOS 的 OpenVPN、LAN 配置、远程访问没有对应能力，未加。
- 页签顺序与 HiveOS 一致：概述、飞行表、超频、Autofan、统计、活动、设定；RigDeck 自有页签排在后面。HiveOS 的“调试”页按每张显卡调矿工参数，RigDeck 的矿工参数在飞行表中设置，未加。
- Autofan：临界温度（40–120°C）与临界动作写入机器策略，随策略推送到矿机，看门狗每 10 秒取 CPU 与全部显卡的最高温度。停止挖矿软件后期望状态仍是运行，降到临界温度以下 10°C 自动恢复（重启后也会恢复）；重启 / 关机与算力监视器共用整机重启间隔。风扇转速本身仍由超频配置、驱动或 BMC 管理。
- 统计：上一个 / 日期 / 下一个，1d / 3d，导出 CSV（长表：时间、指标、数值）；图表上方是按级别筛选的事件时间轴。历史接口新增 `until` 参数；6 天内的单日窗口读原始样本，其余读分钟聚合。
- 设定：ID、名称、描述、标签、维护模式（开机不启动矿工、算力监视器暂停，温度保护照常）、挖矿软件延迟（开机后延迟启动，独立进程等待，不阻塞开机单元）、硬件功耗与电源效率（列表与单机功耗按 (测得 + 硬件) ÷ 效率 估算墙插功耗，并在提示里注明是人工设定）。描述等设置存在机器策略里，修改会触发一次策略下发。

验证：运行层单元测试 31 项通过（新增温度保护 4 项、开机启动 1 项）；Rust 工作区测试通过（依赖 PostgreSQL 的用例未运行）；前端类型检查、生产构建通过；模拟接口的 Playwright 用例 20 项通过（新增 4 项）。未在真实矿机上触发过温度保护、维护模式或开机延迟。

### 视觉对齐与币种图标

- 配色、字号、圆角、内容宽度改为在 HiveOS 页面实测的计算样式：正文背景 #22262b，顶部区块 #1d2125，卡片 #262b31，行 #2f353c，正文 #c6ccd2，强调 #eef0f2，次要 #9ba5b1 / #818e9c，橙 #ffae00，绿 #84bf40，红 #ff3733，蓝 #7bbeea；14 px 正文，3 px 圆角，40 px 顶栏。Ant Design 主题同步。
- 页签与 HiveOS 相同：14 px，未选中 #9ba5b1，选中 #eef0f2 并带 1 px 下划线，间距 24 px。矿场统计卡改为 64 px 高、无边框、20 px 细体数字，第一张卡顶部 2 px 条按在线比例显示绿 / 橙。
- 矿机页的操作图标移到顶部导航栏（与 HiveOS 位置相同，手机宽度仍留在页头）；页头与页签行放在全宽深色区块里，去掉了原来的蓝色色条。
- 品牌仍是 RigDeck，没有使用 HiveOS 的标志或图片。
- 币种图标：浏览器只从主控读取。顺序为主控图标库（网页上传、图片链接、CoinGecko 选币，存 `coin_icons` 表；或放进主控图标目录的 `SYMBOL.svg|png|webp|jpg` 文件）→ 内置 cryptocurrency-icons（CC0，482 个，单独打包、按需加载）→ 首字母圆标。CoinGecko 搜索、缩略图和图片下载都由主控发出，候选列出名称、id 与市值排名，解决同符号不同币（如内置的 BTX 是 Bitcore，与用户 HiveOS 里的 BTX 不同）。上传与下载都限制 256 KB，按文件头识别格式而不信任声明的类型；SVG 以 `sandbox` CSP 和 nosniff 返回。之前存在矿场设定里的图标方案已撤掉（未发布）。图标显示在矿机列表、矿机页、钱包、飞行表与选择飞行表面板。
- 钱包表按 HiveOS 拆出“数字货币”列，筛选改为灰色小方块。余额与美元金额列不做（计费类功能不在范围内）。
- 矿机页按 HiveOS 同一台矿机（1200 px 内容宽度）逐块对照重排：页头两行——第一行 ☆ 名称（约 150 px 处换行）、飞行表标记（未应用时红色“无飞行表”）、右侧 LA 三个值与蓝色功耗；第二行 11 px 的已启动时长、挖矿软件状态、矿工名与版本、橙色运行层版本，右侧内核、驱动（N 绿 / A 红）、短型号 × 数量。概述页依次为矿工行（有矿工时）、设备行（44 px，#2f353c，列顺序 HASH / TEMP / 风扇 / 功耗 / LOAD / CORE / MEM，温度默认白色、过热才变色，去掉 VDD 列，电压放到核心频率的提示里）、底部瓦块（56 px：平均载入、剩余内存〔顶部绿条为已用比例〕、功耗〔两位小数〕、系统版本、驱动）和两栏硬件信息。GPU 矿机与 HiveOS 一样只列显卡；只有没有显卡、或 CPU 正在挖矿时才多一行 CPU。没有 HiveOS 的剩余空间、VBIOS、磁盘型号（运行层不采集）。
- 矿机列表行按 HiveOS 同宽逐列对照：勾选框在 23 px 的 #2f353c 条外；☆ 名称（超过 17 个字符时中间省略，如 docker-..monitor）、红色火箭（无飞行表）与告警、运行时间、设备厂商标记（N 绿 / A 红 / I 与 C 蓝，C 表示只有 CPU）、矿工或“无飞行表”、设备方块、LA、FAN（显卡最高风扇转速；纯 CPU 矿机显示 CPU 使用率）、两位小数功耗。设备方块 11 px，每块显卡一个，按温度绿 / 橙 / 红，无读数为灰；CPU 是圆点，只在没有显卡或 CPU 在挖矿时出现。鼠标悬停显示 HiveOS 样式的提示（#16191d、11 px 粗体），如“GPU 0 TEMP 48° FAN 32%”，挖矿时附带该卡算力。手机宽度仍是卡片布局。顶部统计卡固定一行。
- 截图复查后的三处修正：顶部算力合成一张卡（一个币种时大字显示；两个币种各占一行；更多时显示第一个和“+N 种币”，悬停列出全部币种、算法和台数），统计卡固定 7 张一行不再挤压；显卡表只显示核心温度，显存温度放在悬停提示里，显存达到 100°C 时才在核心温度旁加红色“显存 xx°”标记，矿机列表的 GPU 悬停提示也加了 MEM；掉线矿机行显示红色的掉线时长和“掉线 · 最后在线 月/日 时:分”（从未上报的显示“掉线 · 从未上报”），不再显示 LA、FAN 和功耗的空值。
- 勾选矿机后与 HiveOS 相同：顶栏面包屑变为“‹ 取消选定 N 矿机”，顶栏放批量操作图标，筛选多出“已选择 N”。只放 RigDeck 能真正执行的操作：电源动作（重启 / 关机 / BMC 开机、优雅关机、断电重启、强制断电；主控机器不参与批量重启关机）、部署运行层、选择飞行表、超频模版、运行命令、编辑标签（批量添加 / 移除）、多机终端、挖矿软件动作、移除。HiveOS 的 Repo / Server URL、LAN 配置、转移矿场等 RigDeck 没有对应能力，不做空壳。手机宽度时这些图标在列表上方。
- 飞行表页逐个点开对照（只打开不保存）：#363d45 面板、276×67 的选择卡片（前一步未选时标签变暗）、卡片右上角橙色“添加钱包 / 设定挖矿软件配置”、浅色“创建飞行表”、左下“添加自 文件 / 剪贴板”。矿池卡显示在挖矿软件配置里填写的地址（HiveOS 的“挖矿软件配置”选项），没有内置矿池目录，所以不做矿池下拉。挖矿软件下拉带设备标签：RigDeck 内置的 XMRig、SRBMiner-MULTI（--disable-gpu）、cpuminer-opt 只跑 CPU，Custom 由矿工包决定。列表为 所有 / Applied / Not Applied（按矿机上报的正在运行的飞行表判断）、币种 / 钱包 / 矿工小方块筛选、HiveOS 行样式和 ••• 菜单（应用到矿机、编辑、复制、导出、剪贴板、移除）。导出与“添加自”用 RigDeck 自己的 JSON 格式，钱包按 id 或“币种 + 钱包名”匹配。HiveOS 的 Owner's（多用户）、默认设置（自动建机）、创建活动（日程）RigDeck 没有，不做。
- 新的钱包弹窗与挖矿软件配置弹窗：#363d45 弹窗、字段为带内嵌标签的 #262b31 方框、蓝色 ⓘ、取消为文字按钮、主按钮橙色；从飞行表任务打开时币种锁定为该任务的币种。保留 RigDeck 的“备注”；不做 HiveOS 的“保存为全局钱包”（无多矿场）和“获取钱包余额”。按钮文字不再自动插入空格（“取消”而非“取 消”），与 HiveOS 一致。
- 矿机命令弹窗：>_ 输入框与“运行”按钮、可选超时、最近使用的命令（取自 RigDeck 任务记录，排除工具栏自己的重启 / 关机脚本）、常用命令（换成 RigDeck Ubuntu 矿机上可用的命令，不列 HiveOS 专有的 nvtool、hello 等）。单机工具栏和批量栏共用。
- 选择飞行表：与 HiveOS 一样从火箭图标下拉出面板，币种筛选、飞行表卡片，点卡片后确认应用。HiveOS 的 Unset current FS 在 RigDeck 没有对应操作，不做。
