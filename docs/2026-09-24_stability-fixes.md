# 2026-09-24 稳定性与资源修复

本次修复保留任务、部署与审计历史。数据库新增 `0002_telemetry_and_retention.sql`；矿机运行层为 `0.1.7`。主控与运行层可以分步升级，旧运行层的 system 硬件字段也会在主控入库时拆分。

## 行为变化

| 范围 | 修复后的行为 |
|---|---|
| 矿工控制台 | 普通 SSH 用户通过 PTY sudo 握手提权；仅在关闭回显并收到专用提示后发送密码，密码不进入命令行或终端输出。root 直接连接。 |
| 遥测 | 每台机器独立循环；SSH 首次失败跳过本轮剩余类型；BMC 电源、传感器、事件独立周期为 30、60、600 秒。删除机器后取消其采集任务。 |
| 硬件与历史 | hardware 仅保存最新观察值，小时级采集；动态 system 不再带 CPU 拓扑、主板、BIOS、接口清单。详情接口合并硬件以兼容页面。历史字段在 SQL 中裁剪，取最新 10000 条后正序返回。 |
| 指标维护 | 先独立提交未来 14 天分区，再按持久化游标逐小时处理分钟数据；每批单独提交，重叠两分钟接收延迟提交。删分区使用独立短事务和 2 秒锁超时，清理语句各自提交。 |
| SSH | 不再达到 128 条就清空连接池；认证和打开通道各有 15 秒超时。sudo 模式按连接与凭据摘要缓存 5 分钟。 |
| 任务 | 10 秒心跳，单次等待最多 5 秒；短暂不可用可重试，距上次有效续租接近 50 秒时停止本次调度并保留对账语义。取消信号复用心跳。结果保存可重试，绝不为重试保存而重新发送电源或矿工动作。 |
| 登录 | 以来源 IP 与用户名的摘要计数；仅显式启用可信代理模式时读取 CF-Connecting-IP。 |
| 终端重连 | 先解绑旧 socket 全部回调，再关闭连接，防止迟到的 close 删除新连接发送函数。 |
| stop | 进程归属检查后发生退出时，忽略 ProcessLookupError，继续提交 stopped 状态。 |
| 容器停止 | Linux 同时处理 SIGINT 和 SIGTERM。 |
| 机器删除 | 软删除，保留任务和部署引用；仍有排队、运行、对账或结果不明任务时返回冲突，避免丢失操作归属。 |
| 安装包 | 上传、URL 导入和 SSH 分发采用有界分块；缓存 SHA256 在 spawn_blocking 中流式计算，矿机端也分块验证，已存在版本优先复用。 |
| 任务输出 | 列表保持 output 字段为空，完整输出只在详情返回；相同进度不重复写数据库。 |
| Redfish | 按 CA 配置复用 HTTP Client，集合已有展开成员时不逐条重新请求；仍支持只含链接的设备。 |
| 本地保留 | 每小时清理；保留当前、已提交及最近两个版本，其他版本至少保存 7 天；不删除保留版本引用的软件包，未引用包至少保存 7 天。存在不确定操作时保守跳过。完成 30 天的操作删除输出和大快照，但保留轻量完成记录与请求摘要防止重放。 |
| 页面与时钟 | CSRF 在会话查询完成前同步设置，401 回到登录；批量控件和 BMC 列表使用摘要。浏览器使用主控响应时间校准新鲜度；新版运行层以开机单调时间计算样本年龄，主控转为自己的时间。 |
| 其他 | SSH 用户名允许点；补齐 machine_id 索引；备份包含 cloudflared Compose 覆盖文件。 |

分钟表保存该分钟最后一个数值样本及采样时间，不保存硬件快照。已有历史大 JSON 不在升级事务中全量重写，查询会裁剪，旧原始分区按原有 7 天策略淘汰。运行层未知、运行中操作记录不会被清理。

## 部署与回退

1. 备份 PostgreSQL、代码、Compose 覆盖文件和 `.env`，保存旧镜像标签。密钥仍单独保管。
2. 更新应用镜像并保留数据卷。启动时 SQLx 执行新增迁移，不修改 `0001_core.sql`。
3. cloudflared 部署启用 `RIGDECK_TRUST_PROXY_HEADERS=1`，只适用于源站端口仅能通过本机可信代理访问的部署。直接公网开放源站时不要启用；默认使用 TCP 对端 IP。
4. 分批更新运行层脚本并重启 watchdog，保留矿工 screen、实例状态和飞行表。确认版本、PID、数据新鲜度和硬件字段。
5. 应用回退使用备份镜像及配置；数据库回退需要在停写后恢复备份，不能在线删除迁移记录。旧程序不识别软删除，因此产生软删除记录后不得仅回退旧程序继续管理。
