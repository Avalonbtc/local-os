# 2026-09-25 矿机自行下载、批量添加与界面精简

这一轮按 HiveOS 的方式调整：矿机自己下载挖矿软件，飞行表直接填写矿池，去掉用不到的页面，任务结果统一放到每台矿机的“消息”里。同时补上批量添加矿机，并审查了 BIOS 在线修改和软件功耗读数。数据库新增迁移 `0004_inline_miner_and_pool.sql`，运行层版本升到 `0.2.0`。

## 批量添加矿机

矿机列表的“批量添加”分三步：

1. 填写地址和共用凭据。地址支持单个 IP、`10.0.0.10-60`、`10.0.0.10-10.0.1.20`、CIDR（/22–/32），以及 `名称,地址[,端口[,用户]]`。名称模板支持 `{last}`、`{last2}`、`{ip}`、`{n}`、`{n:3}`。每批最多 256 台。
2. 主控并发（16）读取 SSH 指纹，列表逐台显示指纹或错误，勾选确认。
3. 创建机器，逐行返回结果。可选创建后立即部署运行层：并发 8，先在 1 台上验证。如果部署任务没能提交，机器仍然会添加，界面会提示重新部署。

接口：`POST /api/v1/ssh/host-keys`、`POST /api/v1/machines/batch`。同名、缺少凭据、重复名称逐行报错，不影响其他行。

## 矿机自己下载挖矿软件

- 飞行表的每个任务直接带上挖矿软件：适配器、名称、版本、下载链接、可选 SHA256，原生适配器还有包内执行文件。不再引用“矿工软件”“矿池”“币种”目录。
- XMRig（6.26.0 / 6.25.0 / 6.24.0）和 SRBMiner-MULTI（3.4.6 / 3.4.5 / 3.4.4）内置 GitHub 官方 Linux 版本，也可以填写镜像地址。cpuminer-opt 没有官方 Linux 二进制包，需要自己填写下载链接。Custom 是标准 HiveOS 自定义包。
- 应用飞行表时，主控只通过 SSH 让矿机执行 `rig-miner fetch-package <sha256|-> <url>`：
  - 填了 SHA256：矿机已有该包就直接使用；没有就下载，并校验 SHA256。
  - 没填 SHA256：只允许 https；矿机按链接记录已下载的包（`cache/url-index.json`），再次应用时不会重新下载。之后按实际下载内容的 SHA256 部署。
  - http 链接必须填写 SHA256。没填 SHA256 时，下载过程中的重定向也只允许跳转到 https 地址。
- 主控不再保存、转发或通过 SSH 上传安装包。上一轮草稿里的 `/dl/{token}` 下载地址和 `RIGDECK_PACKAGE_URL` 已删除。
- 旧飞行表里已经上传到主控的 `cache:` 包：只要矿机上已有这个包，就继续可用；新机器没有这个包时，会提示“请在飞行表中填写 http(s) 安装链接”。
- 下载失败时这次应用直接记为“失败”并解除机器锁定（矿机上还没有启动任何东西），不会变成“结果不明”。消息里会显示 curl 的原因，例如 `Could not resolve host: github.com`。如果矿机访问 GitHub 困难，请在“其他版本 / 镜像地址”里填写可访问的地址。

## 飞行表（和 HiveOS 一致）

每个任务依次选择数字货币、钱包，直接填写矿池（每行一个，第一行为主矿池），然后选择挖矿软件。“设定挖矿软件配置”里可以设置版本或下载地址、算法、钱包与矿机模板、矿池、密码、额外参数、线程数和 CPU 绑定。Custom 的配置项与 HiveOS 相同。

迁移 `0004` 自动转换已有飞行表：原矿工目录的内容写入任务；原来选择的矿池，如果任务没有单独选服务器，就写入这个矿池的全部地址；原来 Custom 矿工自带的矿池地址、算法、钱包模板、密码和其他配置参数，在任务没有设置时也会写入任务，重新保存飞行表不会丢失。`miners` 和 `pools` 表中的数据保留，但界面不再使用。

## 去掉的页面

## 精简上报数据

运行层 `0.2.0` 的 system 数据不再包含磁盘、网络接口流量和网卡清单。内网 IP 保留，读取结果缓存 60 秒，watchdog 不再每 10 秒启动一次 `ip` 命令。主控入库时也会删除旧版运行层上报的 `disks`、`network` 和 `interfaces`，所以升级主控后数据库写入量立即下降，不必等所有矿机都更新运行层。单机页的“网络接口”和“磁盘”表已删除，改为显示内网 IP。

## BIOS 在线修改：审查与修复

整体设计是可靠的：只提交修改项；写入前重新读取并比对配置版本；操作日志持久保存，结果不明时不会自动重试；不会自动重启；密码只通过 stdin 传递。发现并修复了以下问题：

1. **待生效修改无法清除，会永久阻止写入。** 如果重启后固件没有采用新值（例如生效条件不满足），`pending` 会一直保留，之后的所有修改都会被拒绝。现在“读取 BIOS”支持 `discard_pending: true`，界面在待生效提示里增加“已重启，清除标记”：重新读取 BIOS，并把回读值当作最终结果。
2. **同一台机器的 SUM 锁被占用时，新操作被标记为“结果不明”。** 这会锁住机器，而且对账时找不到操作记录，永远无法恢复。现在新操作直接失败（实际没有执行），只有对账请求仍返回“不明”。
3. **崩溃后遗留的空操作目录会让重试失败。** 创建操作目录后、写入日志前如果崩溃，会留下空目录，重试时 `mkdir` 报错。现在允许复用这个目录（此时尚未执行 SUM）。
4. SUM 适配层异常退出时，主控日志会记录 stderr 末尾（密码已替换）。之前 stderr 被直接丢弃，无法排查。
5. BIOS 页面原来链接到已删除的任务页，现在链接到该机器的“消息”。localStorage 读写加了异常保护。

新增 3 个 Python 测试：清除待生效修改、锁被占用、空操作目录。

## CPU 软件功耗：审查结论

`collect_cpu_power` 只统计 RAPL 的 `package-N` 能量差值，不重复计算 core、DRAM 子域。它能处理计数器回绕、重启（boot_id 变化）和超过 60 秒的旧样本；任一 package 读取失败时返回“未采集”，不会显示 0。按名称去重，所以 `intel-rapl-mmio` 和 `intel-rapl` 同时存在时不会重复计算。watchdog 以 root 运行，可以读取内核 5.10 以后只允许 root 读取的 `energy_uj`。没有发现需要修改的问题。

需要注意：

- 这是 CPU 封装功耗，不包括内存、风扇和电源损耗，整机功耗通常更高。界面已标明“CPU 功耗”。
- 汇总栏的“预估日电费”写死为 0.56 元/度。以后需要改为在“设定”中配置电价（HiveOS 在矿场设置中配置）。

## 升级顺序

1. 备份后更新主控。迁移 `0004` 在启动时自动执行。
2. 在矿机列表全选，执行“部署 / 更新运行层”，更新到 0.2.0。**必须先完成这一步再应用飞行表**：旧运行层没有 `fetch-package` 命令，应用时会提示“请先部署运行层”。
3. 打开现有飞行表检查挖矿软件。原来通过主控上传的包仍能在已有这个包的矿机上运行；建议改为官方版本或下载链接，便于新机器使用。
4. 确认矿机能访问 github.com；访问不了时，在飞行表里改用镜像地址。
